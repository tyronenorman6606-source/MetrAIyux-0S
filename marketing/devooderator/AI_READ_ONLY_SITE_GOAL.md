# DevoodeRator Internal Site Goal

READ ONLY FOR AI AGENTS. DO NOT EDIT THIS FILE UNLESS GRAY LONDON SKYES EXPLICITLY SAYS: "edit the DevoodeRator internal goal file."

DevoodeRator is Gray London Skyes' behind-the-scenes founder/dev blog and proof journal. It exists to turn real build days into public, founder-voiced writing: what broke, what got fixed, which languages/tools/agents were used, which receipts prove the work, and how the 0S architecture keeps getting stronger.

The site should feel like a live coding diary, founder operating room, receipt wall, and social-content vault. It is not a generic company blog. It is not polished corporate PR. It should preserve Gray's voice: direct, intense, funny when useful, sovereign, technically specific, and honest about stress, failure modes, recovery boundaries, and proof.

Future blogs must:

- Be written from Gray's first-person perspective.
- Use real work from the day, not fake lessons.
- Include the stack/languages/tools used when known.
- Include proof links, receipts, deploy IDs, smoke checks, stress checks, vault receipt IDs, or explicit "not yet proofed" boundaries.
- Explain the struggle and the architecture gap before celebrating the win.
- Keep secrets, bearer tokens, admin codes, passphrases, raw env values, and private unlock material out of public text.
- Use emoji as light routing glyphs only where it helps scanning or personality.
- Avoid emoji in legal, auth, payment, incident, security, code identifier, and machine-readable proof language.
- Preserve the "ShYT happens, Skye keeps the sKache" boundary: no perfect-tech promises, proof-backed recovery posture.

The site also acts as a future target for SkyeVault Bins. The DevoodeRator source folder, the blog agent instructions, copied social assets, business-card mirrors, and daily post drafts should be eligible for secure vault bin capture without forcing them into a public Git workflow before they are ready.
