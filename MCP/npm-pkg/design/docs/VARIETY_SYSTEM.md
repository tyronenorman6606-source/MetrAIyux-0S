# Skye Design Variety System

The MCP must behave like a high-end design creation system, not a single SkyeSol restyler.

## Rule

Every generated surface needs a design DNA before code:

- archetype
- first viewport structure
- visual subject
- motion language
- proof format
- palette discipline
- typography posture
- conversion path

If two consecutive pages use the same archetype, structure, palette, and proof format, the second page fails novelty unless the user explicitly asked for a family match.

## Archetypes

- `cinematic-command`: living WebGL/object scene, short title, proof rail.
- `app-operating-surface`: real app shell first, dense controls, status, tools.
- `editorial-proof-atlas`: magazine-like proof story, large media, sparse evidence.
- `kinetic-process-funnel`: scroll-led transformation path with staged steps.
- `spatial-product-lab`: interactive product object, specs, toggles, inspection.
- `founder-authority`: founder/media-led trust scene with receipts.
- `minimal-luxury`: restrained, whitespace-heavy, fewer effects, stronger type.
- `field-report`: documentary proof, real screenshots, annotated receipts.

## App-First Guardrail

`app-operating-surface` is not the default for "operator", "system", "tooling", "MCP", or "business" language. Use it only when the user explicitly asks for an app shell, dashboard, admin console, control plane, product UI, portal UI, database console, or inbox UI.

For public sites, homepages, service pages, brand pages, showcases, portfolios, and editorial surfaces, start from `editorial-proof-atlas`, `cinematic-command`, `founder-authority`, `minimal-luxury`, `spatial-product-lab`, or `kinetic-process-funnel` unless the user explicitly chooses an app/dashboard surface.

## Variation Axes

- `layout`: full-bleed scene, app shell, atlas grid, rail timeline, split-stage, radial map, editorial stack.
- `media`: WebGL object, real screenshot, proof video, founder image, product photo, code console, database map.
- `motion`: subtle drift, pinned scroll, kinetic cards, cursor field, theatre direction, video reel, no-motion luxury.
- `palette`: obsidian/gold/cyan, ivory/ink/red, black/silver/green, white/charcoal/gold, deep green/gold, legal neon.
- `type`: editorial serif, industrial grotesk, mono-console, luxury display, compact label.
- `proof`: live app screenshot, browser-action video, receipt timeline, QA ledger, before/after, operator notes.

## Required Workflow

1. Call `design_variety_plan`.
2. Pick one returned direction.
3. Pull its pattern pack with `design_pattern_pack`.
4. Pull open-source recipes with `design_open_source_stack`.
5. Build source with real imports/runtime behavior.
6. Run audits and browser QA.
7. Record the chosen design DNA in the project receipt.

## Rejection

Reject outputs that:

- reuse the same dark dashboard/card template with swapped copy.
- use SkyeSol living background as the only idea.
- claim variety while keeping identical hero, cards, palette, and proof layout.
- use all available effects at once instead of a chosen motion language.
- ignore real product surfaces when screenshots or workflow proof exist.
