# Skye Design Lab User Guide

This lab helps you create premium landing pages, product pages, and client-facing experiences with the Skye/Spectacle design language.

## What This Is

Skye Design Lab is a design source for:

- Cinematic website heroes.
- Scroll-based product funnels.
- 3D product or command-center scenes.
- Proof-backed trust panels.
- Founder/operator authority sections.
- Better MCP-assisted website generation.

It is not a normal template pack. It is a system for making pages feel expensive, intentional, and alive.

```bash
cd /workspaces/MetrAIyux-0S/skye-design-lab
npm run dev
```

Use it as a direction board before building a client site.

## The Main Design Rule

Do not build boring landing pages.

A page should have:

- One strong visual subject.
- Short hero copy.
- A clear call to action.
- Motion that supports the story.
- Proof that feels client-safe.
- Mobile layout that looks intentionally designed.

## What To Ask For

Good requests:

- "Build a cinematic command hero for my database product."
- "Create a scroll funnel showing signup, setup, proof, and handoff."
- "Use the founder authority scene with my portrait and proof metrics."
- "Make this page feel like SkyeSol but tailored to my product."

Bad requests:

- "Make a generic landing page."
- "Add some cards."
- "Use whatever looks good."

## What Should Never Appear Publicly

Do not put these on a public sales page:

- MCP smoke-proof messages.
- Internal script names.
- Debug output.
- Build logs.
- Database credentials.
- Raw operator notes.

Those belong in private proof or admin surfaces.
