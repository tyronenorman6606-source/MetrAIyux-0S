Verification protocol

Trust controls for a live seeded business platform.

The platform separates seeded records, owner claims, duplicate review, suppression, and buyer-facing verification signals so the directory can scale without pretending every scrape row is fully owner-confirmed.

Seeded

Provider-supplied or public-data listing

Default listings are useful but not overclaimed. Missing contact, owner, or pricing details stay visible in quality reports.

Claim

Owner update packet

Businesses can generate claim/update packets without local auth. Upstream auth can gate submission and review.

Suppress

Removal control

Confirmed fake, duplicate, or abusive entries can be suppressed by id, identity key, domain, phone, email, or source hash.

Operator rule

Do not sell “verified” as owner-confirmed unless the seed field says it.

The build can display licensed, reviewed, insured, no-hidden-fee, mobile, and request-ready signals only when those fields exist in the seed data.
