Drive and vault

How the repo, SkyeVault, and MyDrive split responsibilities.

MyDriveLocal/offline IndexedDB vault with encrypted JSON backup export and import.
SkyeVault ProCustomer/operator local vault, SkyeDocxMax bridge, and local import folder workflow.
SkyeVault DropDeveloper/repo push lane with sanitized archives, R2/SkyDrive streaming, and secret boundary receipts.
# Stage sanitized local material for SkyeVault Pro import
npm run vault:pro:stage -- --source <folder> --out <local-import-folder>
npm run vault:pro:from-dev -- --out <local-import-folder>
npm run vault:pro:stage:latest -- --out <local-import-folder>

# Safe smaller repo archive lane
npm run vault:dry-run
npm run vault:push

# Full repo SkyDrive / R2 streaming lane
npm run vault:repo:full:dry-run -- --max-gb=100
npm run vault:repo:full -- --max-gb=100

# Secret boundary manifest
npm run vault:secrets:manifest

Proof policy

Deep smoke is not live proof.

The repo rule still stands: production-facing changes need a deployed headed-browser pass on desktop and mobile before a live link is called ready.

# Required after deploy for production closure
npm run proof:live-browser -- --url https://metraiyux-0s-full-system.graylondonskyes.workers.dev/devs-playbook/login.html?key=skdevpbk --expect "Devs Playbook access"

# This closure only ran local/deep smoke unless a later handoff says otherwise
