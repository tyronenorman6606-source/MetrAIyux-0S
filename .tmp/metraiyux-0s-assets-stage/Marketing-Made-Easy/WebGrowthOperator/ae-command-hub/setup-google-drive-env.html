Production rule: this lane is Cloudflare Worker only. No Netlify function and no Google Drive folder is required for the production packet flow.
Required before live submissions

Cloudflare encrypted packet vault
for AE and vendor onboarding.

The onboarding form posts to /api/marketing-made-easy/ae-vendor-onboarding/submit. The Worker validates the packet, encrypts payout data and uploads, stores packet records in Cloudflare KV, and blocks payout release until owner/admin verification.

Required Cloudflare bindings

  • SITE_EVENTS_KV bound in metraiyux_0s_site/wrangler.toml.
  • AE_VENDOR_PACKET_ENCRYPTION_KEY_BASE64 stored as a Cloudflare Worker secret.
  • Shared FS27/SkyGate session or admin token available for protected submissions.

Generate the encryption secret

openssl rand -base64 32 | npx wrangler secret put AE_VENDOR_PACKET_ENCRYPTION_KEY_BASE64 --config metraiyux_0s_site/wrangler.toml

Do not commit the generated value. It must decode to exactly 32 bytes because packet encryption uses AES-GCM.

Go / no-go checklist

Use this after deploy before handing the lane to any AE, vendor, or client.

Cloudflare only

Pass conditions

  • /api/marketing-made-easy/ae-vendor-onboarding/health returns encrypted_storage: true.
  • /ae-command-hub/onboarding.html posts to the Cloudflare API path.
  • Unauthenticated submission returns 401.
  • Authenticated valid packet returns 201 with a receipt ID.
  • Packet list is readable only through the protected API.
  • Response bodies do not expose routing numbers, account numbers, or raw W-9 bytes.

Boundary

This creates an encrypted onboarding packet and payout ledger. It does not send external ACH, Stripe, PayPal, Cash App, or check payments by itself. External money movement still requires owner approval, partner/vendor terms, and the configured payout provider lane.
