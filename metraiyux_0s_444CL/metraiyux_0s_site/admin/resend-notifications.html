Email Approval Layer

Use Resend to notify you when the automation brain needs approval.

The Main Automation Brain can route and draft automatically, but risky actions trigger email approval notifications before publishing, sending, committing, hiring, paying, or making public claims.

Required Cloudflare secrets and vars

npx wrangler secret put ADMIN_TOKEN
npx wrangler secret put RESEND_API_KEY
[vars]
RESEND_FROM_EMAIL = "13-Department Approval Desk <approvals@your-domain.com>"
ADMIN_APPROVAL_EMAIL = "you@your-domain.com"
PUBLIC_ADMIN_URL = "https://your-domain.com"

Use a verified Resend sending domain for production. Keep the API key as a Worker secret, not in public site files.

When emails fire

Email notifications are created when a chat command includes approval-sensitive actions, when a social draft is queued, or when an admin task is explicitly marked approval-required.

  • Publishing or posting content
  • Sending email or external messages
  • Pricing, refunds, or payments
  • Contracts, signatures, filings, legal/tax/HR-sensitive items
  • Public claims or proof-sensitive launches

Smoke test

curl -X POST "$WORKER/api/admin/approval-email/test" \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message":"Test approval email for Main Automation Brain."}'

Then open Admin Approval Inbox and record a decision.

Autonomy boundary

This creates real email notifications once deployed, but external business actions still require approval unless you intentionally change policy and configure provider connectors. That is the correct serious setup.
