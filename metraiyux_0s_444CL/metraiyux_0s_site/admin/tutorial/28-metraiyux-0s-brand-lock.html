Lesson 28

Client Command Deck Brand Lock

Use this lesson to keep the whole site, admin layer, SaaS layer, brain registry, Worker docs, and customer-facing language under one official platform name.

Official naming rule

Client Command Deck is the product name. The 13-department model is the operating framework, not the product name. Prior names are release history only.

Public site

Lead with Client Command Deck. Explain it as a autonomous business command deck for owner-admin command, customer SaaS workspaces, and approval-gated automation.

Admin layer

Call the protected owner side the Owner/Admin OS. The Main Automation Brain remains the primary owner-side orchestrator.

Customer layer

Customer signup, onboarding, dashboard, commands, and workspaces must stay tenant-scoped. Customers do not access owner credentials or production connectors.

Security Gate Brain

Security Gate Brain is the QA/security assistant. It reviews tenant boundaries, approval risk, privilege escalation, public claims, and system-audit concerns.

Cloudflare layer

Worker, D1, KV, Queues, and Resend are deployment infrastructure. They support Client Command Deck; they are not the brand.

Valuation language

Use the Client Command Deck name when describing packaged value, deployed value, and future SaaS valuation.

Smoke test

  1. Open the homepage and confirm the hero says Client Command Deck.
  2. Open the brand system page.
  3. Open the customer SaaS page and confirm it does not imply access to owner/admin connectors.
  4. Open Security Gate Brain and confirm it is positioned as security/QA.
  5. Open valuation and confirm the selected name is used.

Client Command Deck tutorial. Production use requires deployed Workers, auth, secrets, connector credentials, and verified approval policy.
