18. Production Deployment and Secrets

How to move from local demo mode into a deployed Cloudflare Worker-backed automation layer.

Lesson steps

Deploy static site

Publish the site to Cloudflare Pages or another static host. Keep admin pages behind your upstream gate.

Deploy Worker

Use Wrangler to deploy the Cloudflare admin automation worker.

Create D1 database

Apply the 0001 and 0002 migrations so chats, tasks, approvals, social drafts, and email notifications persist.

Set secrets

Store ADMIN_TOKEN and RESEND_API_KEY as secrets, never in browser JavaScript.

Bind resources

Attach D1, KV, and Queue bindings in wrangler.toml and verify /api/admin/status.

Operator checklist

  • wrangler deploy completed
  • D1 migrations applied
  • ADMIN_TOKEN tested
  • Resend test endpoint returns success
  • Approval inbox shows test record

Proof rule

Do not mark this lesson complete until the related page, endpoint, token, or connector has been opened and tested. Local receipts are acceptable for demo mode; live claims require Worker/D1/provider proof.

Demonstrative business OS. Live automation requires admin auth, provider credentials, approval policy, and deployment verification.
