Hard Limits (Non-Negotiable)

These gates are baked into the brain routing logic, the Worker endpoints, and the security scanner. They cannot be configured away. They exist because an operating system that will do anything you ask is not an operating system — it's a liability.

  • No contract will be produced, signed, or sent without a human approval receipt
  • No payment, transfer, or financial commitment will execute autonomously
  • No hire, termination, or placement will complete without human sign-off
  • No legal filing, tax action, or compliance document will be submitted without approval
  • No public communication — social, press, or public claims — will publish without a human release
  • Every brain routing decision and security scan is logged to D1 with timestamp and outcome
  • Customer workspace commands cannot reach owner-scoped brains or other tenants
Deployment Requirement

A Cloudflare account (free tier is sufficient for Workers and D1). A Resend API key (free tier for email). Stripe keys for billing (optional if not using SaaS provisioning). SkyeGate token for admin auth (or Cloudflare Access as an alternative). No other cloud dependencies.

Objection Handling

The hard questions, answered straight.

These are the questions buyers always ask. We've answered them honestly, including the ones where the honest answer is "not yet."

"You said 16 brains — but it's not actually AI, right? It's just keyword matching?"
Correct. The brain routing layer uses structured keyword classification and regex pattern matching to determine which functional domain a command belongs to. There is no large language model making inferences in the browser. The system is deterministic and auditable. If you issue the same command twice, you get the same routing outcome. That predictability is intentional — it is what makes the approval gates and proof receipts meaningful. An LLM endpoint can be wired into the Worker if you want semantic understanding on top, but the platform's core value is the routing structure, the audit trail, and the approval gates — not language model output.
"Is this deployed and running in production right now?"
Yes. The full system is live at metraiyux-0s-full-system.graylondonskyes.workers.dev — serving from Cloudflare's global edge right now. All six Workers are deployed and returning responses: Admin Automation, SaaS Provisioning, 0meg4kAI Security Gateway, CROWN, NEXUS, and QUANTUM Site Operator. The public spectacle overview is live at metraiyux-0s-public-spectacle.pages.dev. The SkyeGate auth platform is live at skyegatefs27-citadeldb.graylondonskyes.workers.dev. You are looking at a deployed system, not a demo.
"Who are the cabinet executives — are they AI or human?"
The 13-cabinet structure is an autonomous AI command model. Each cabinet seat is a configured brain — a named functional intelligence that routes work for that domain, generates receipts, and enforces its approval gates. The CEO brain routes command decisions. The Legal brain flags compliance risk. The Finance brain gates payment actions. None of them are human hires — the entire point is that your company operates through the command structure without needing to staff 13 executives. The brains are the executives. That is the product.
"Why would I pay $1,497/mo when I could build this myself?"
You could. The tech stack is vanilla JS, Cloudflare Workers, and standard APIs — nothing exotic. The honest answer is that building something of equivalent scope and depth would take a senior developer 3–6 months minimum, at $100K–$200K in engineering cost, and would not include the operational content (522 pages, 722 knowledge base chunks, sales enablement library, government readiness package, admin tutorial). If you have that time and budget and prefer a custom build, do that. If you want something deployed and operational now — with the Worker backend, tenant isolation, approval gates, and proof receipts already wired — that's what you're paying for.
"Is there a lock-in? What if I want to leave?"
There is no proprietary cloud lock-in. The static site is plain HTML/CSS/JS and deploys to any host. The Workers run on your own Cloudflare account — not ours. The D1 data is yours. The code is yours. If you want to stop paying and continue operating what you deployed, you can. You would lose access to updates, support, and new Worker kits, but the system you already deployed continues to run.
"What happens if Cloudflare has an outage?"
The static site continues to serve — Cloudflare Pages has a separate availability tier from the Worker backend. The Worker-dependent features (D1 persistence, live approval emails, multi-tenant provisioning) would be temporarily unavailable. In that window, the browser-local mode handles routing and receipts in localStorage. Cloudflare's global network has better uptime than most on-prem or AWS-hosted alternatives for small companies, so this is a lower risk than it sounds, but it is a real dependency worth noting.
