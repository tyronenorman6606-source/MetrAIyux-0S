Ops / Admin Notes

How it works

Dispatch-ready once approved
  • Onboard once → you become eligible for dispatch when a matching scope opens.
  • Each assignment is defined with deliverables, pay terms, acceptance criteria, and timeline.
  • You stay independent; schedule constraints only apply when the scope requires them.

Approved status does not guarantee a minimum volume of work. Onboarding exists to keep placement fast, accurate, and professional.

Baseline standards

Outcome-driven
  • Professional client communication
  • Delivers to scope; follows SOPs
  • Responsive availability updates
  • Proof of work required (portfolio/examples)
  • Licensing/insurance verified when applicable

For regulated lanes (legal, tax, healthcare-adjacent, security, certain installs), credentials must be verified before placement.

Ops / Admin notes

How to turn this into a true console
Reality check

A real “console” usually means you can view submissions, filter by lane, and dispatch contractors. Netlify Forms is great for intake, but securely reading/processing submissions from the browser is not ideal without a backend.

Cheapest production-ready upgrade paths
  • Option A (fastest): Netlify Forms → email notifications + Zapier/Make → Google Sheet/Airtable for filtering + assignment.
  • Option B (cleanest): Supabase (free tier) → store submissions → secure admin login → true dashboard read/write.
  • Option C (if you already use Firebase): Firebase Auth + Firestore submissions + role-based admin view.
Recommended next step

Tell me which backend you want (Supabase or Firebase) and I’ll generate the next version as a real admin console: login, submissions table, filters, status tags (New/Verified/Dispatched), and export.

Netlify intake wiring tips

No backend needed
  • After first deploy, Netlify detects the form named contractor-network-onboarding.
  • Enable email notifications in Netlify: Forms → Notifications.
  • For automation: connect Netlify Forms to Zapier or Make and push into a Sheet/Airtable.
