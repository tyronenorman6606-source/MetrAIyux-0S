🧭 Deployment process

How I would run a white-label engagement.

From intake to first invoice, a standard white-label deployment takes about 10 days. Most of that is brand configuration, route setup, browser testing, and handoff because the platform is already built.

Day 1–2

Intake and brand configuration

Collect the client's brand assets, domain direction, service model, operating roles, and command lanes. Run the brand replacement pass across the public site and update cabinet persona definitions.

Day 3–5

Deploy static site to Cloudflare Pages

Deploy the branded public surface, verify the domain, confirm protected admin routing, run link audit, and confirm the public and private surfaces resolve cleanly.

Day 5–7

Deploy and configure the 8 Workers

Configure the protected backend, access bridge, approval notifications, proof records, and command routes privately. Verify each live surface responds correctly and writes receipts where receipts belong.

Day 7–10

Smoke test and admin onboarding

Walk through the admin brain chat, issue test commands, verify routing receipts appear in D1, confirm 0meg4kAI quarantine triggers for test violations, confirm approval email fires. Walk the client through the admin tutorial and their specific operating workflows.

Day 10+

Handoff and recurring billing starts

Deliver the handoff documentation kit. Start the client's monthly billing. The platform is live, the client is operational, and you collect recurring revenue on infrastructure you deployed once.

❓ Common questions

What I expect builders and agencies to ask.

Can I customize the brain structure for each client?
Yes. The brain routing system uses JSON persona definitions and a keyword classifier. You can add, rename, or reconfigure cabinet brains for each client's actual operating structure. A construction company doesn't need a Staffing brain. A staffing firm doesn't need a Construction Materials brain. The configuration is per-deployment.
What if the client already has web infrastructure?
I treat that as part of the deployment intake. The public offer does not need to expose how the backend is wired; I map the existing stack, choose the cleanest route, and deploy the command deck without making the client read an infrastructure manual.
Does the client need to understand the deployment stack?
No. They need to understand what the command deck does for their business. I handle the deployment stack privately, verify it in browser, and hand them the live surfaces, admin access path, and operating documentation they actually need.
What happens when MetrAIyux 0S ships updates?
You receive the updated Worker kits and static site patches. Applying them to client deployments is your responsibility as the white-label licensee — it's a re-deploy operation, not an automatic update. For clients on managed hosting through you, this is part of what the monthly fee covers.
Can a client add their own team members to the admin layer?
Yes. SkyeGate handles this via the allowlist configuration in the auth bridge — you add email addresses permitted admin-scoped access. Cloudflare Access policies can be configured per user or per group. A team of five people can all have access to their admin brain and approval inbox with different role scopes if needed.
