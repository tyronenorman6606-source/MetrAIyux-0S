Public technical stack

Enough technical detail to build trust, not enough to expose the control plane.

Here is the architecture a buyer can evaluate: static surfaces, edge workers, scoped data, approval gates, local brain files, and proof records. Account IDs, secrets, live connector setup, and operator runbooks stay off the public floor.

Frontends

Static public overview, full public website, customer SaaS pages, admin interfaces, proof pages, calculators, guided tools, and local browser workspaces.

Built to run fast on a static host while still connecting to worker APIs where persistence or review is needed.

Edge workers

Worker kits exist for site operator routes, NEXUS automation, admin automation, SaaS provisioning, security gateway, sentinel/crown operators, and approval workflows.

The public overview describes the pattern; actual bindings and production control remain private.

Data stores

D1 is used for structured events, tasks, approvals, customer isolation, and tenant records. KV supports fast configuration and state where appropriate. Queues support asynchronous work.

The system is designed around scoped records instead of anonymous blobs.

Brains

Local JSON and markdown brain files carry company doctrine, cabinet scopes, retrieval sources, routing language, and safety boundaries.

The browser-local brain layer can work without a paid model provider; stronger providers can sit behind private server-side connectors.

Approvals

Approval inboxes and email paths can support review before publication, production-sensitive action, customer-to-admin escalation, or connector use.

Public pages mention the workflow; they do not publish credential setup.

Proof

Proof vaults, smoke results, link audits, claims ledgers, and policy documents create a record of what was reviewed, tested, accepted, or blocked.

This is the evidence layer that keeps the system from becoming theater.

MCP gateway language

The scanned MCP bundle points toward tool-facing server patterns, live smoke checks, and credential-aware proofs.

That influence appears here as public language around gateway discipline and evidence, not as exposed tool credentials.

Plain English architecture

Static where it should be. Worker-backed where it must be. Private when it controls power.

Public stack boundary

Buyers can see the shape of the stack: Cloudflare Workers, Pages, D1, KV, Queues, Resend-style approval email, local brains, and proof receipts. Command-line deployment steps, exact tokens, secret setup, private worker URLs, and internal smoke-test procedures stay private.
