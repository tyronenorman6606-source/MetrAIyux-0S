16-brain operating model

Sixteen named brains. Each owns one function. No overlap by design.

Two command brains handle global routing and automation. Fourteen cabinet brains own specific functions: operations, sales, client success, finance, legal, HR, technology, marketing, government readiness, partnerships, QA, and expansion. Commands route to the right brain deterministically — same input, same outcome every time. 0meg4kAI runs security review on every path.

Deterministic routing

Same command in. Same brain every time.

Brain routing is keyword classification — not inference, not best-guess LLM output. A finance command hits Naomi Sterling. A legal flag hits Julian Mercer. The path is predictable, auditable, and logged in D1 on every pass.

Hard gates

Contracts, payments, hiring, and publishing cannot be configured away.

Naomi Sterling (Finance), Julian Mercer (Legal), Sienna Brooks (HR), and Valentina Reyes (Marketing) all own approval gates that exist in the brain router, the Worker endpoint, and the 0meg4kAI scanner — three separate layers, same hard stops.

Isolation by design

Customer brains and owner brains are structurally separate.

0meg4kAI exists to enforce the boundary at runtime. A customer workspace command cannot reach the owner command layer by design — it is Worker-level enforcement, not a policy setting that can be toggled off.
