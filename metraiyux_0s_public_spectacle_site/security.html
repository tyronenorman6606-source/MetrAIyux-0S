Security and isolation

The owner brain and customer workspaces do not belong in the same room.

MetrAIyux 0S treats tenant separation as a product feature. Public visitors can learn the model; customers can use scoped workspaces; the founder's admin command, credentials, production connectors, and private runbooks stay behind the control layer.

Approvals

Human authority stays visible.

The system can draft, route, and prepare work, but sensitive action should pass through approval gates and proof records before it becomes real.

Proof

Security is recorded.

Receipts, ledgers, policy pages, smoke checks, and link audits give the operating layer a history, not just a promise.

Private surface

Clear education. Private control.

Visitors can understand the guardrails without receiving the keys to the building.

Never publish here

  • Secrets, API keys, tokens, provider credentials, or account IDs.
  • Live deployment commands and connector configuration procedures.
  • Admin-only tutorial steps, internal runbooks, or operator checklists.
  • Customer tenant records, private ledgers, production queues, or unreleased proof.

Practical controls

Security here is mostly about permission, evidence, and separation.

The full build includes Cloudflare worker kits and D1 migrations for tenant isolation and security gateway behavior. The public site describes that posture, then routes qualified users to the full website instead of turning this page into a deployment manual.

Tenant boundary

Customer records are scoped.

Customer workspace commands should become customer records first, not direct instructions to the owner layer.

Admin boundary

Owner commands stay private.

Admin pages, connector control, production review, and deployment setup belong behind authentication and operational policy.

Claim boundary

Public claims get reviewed.

The system should not overstate certifications, legal status, production enforcement, or live integrations without proof.

Action boundary

Risky actions need a gate.

Send, publish, provision, escalate, charge, or production-touching actions should leave an approval trail.
