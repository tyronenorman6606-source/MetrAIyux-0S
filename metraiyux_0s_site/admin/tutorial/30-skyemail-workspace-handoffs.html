Client welcome lane

SkyeMail workspace handoffs

Use this lane when a business owner needs a clean SkyeMail workspace, QR welcome card, claim link, mailbox address, and SkyeMerit launch prompt. Founder Command keeps the handoff receipt; the client sets or changes their own password through the shared gate and vault setup.

Open handoff laneOpen handoff APIMailbox offboarding

1. Pick the workspace

Use the business name, owner email, handle, mailbox local part, and domain. For the 0S owner lane, use the built-in MetrAIyux-0s main workspace action.

2. Create the packet

Founder Command calls SkyeMail workspace provisioning when the service token is configured, then stores the QR claim packet and key-card handoff receipt.

3. Send the owner

Send the welcome email or show the QR in person. The packet includes the workspace, mailbox, claim link, and welcome copy, not a permanent plaintext password.

4. Client claims control

The owner opens SkyeMail, signs through the shared 0S Gate, sets the vault key, and can change their password/recovery path without needing a new workspace.

5. Make it fun

SkyeMail shows a Launch Spark experience and can offer an owner-approved SkyeMerit for a free content/ad boost after useful inbox activity.

6. Keep receipts

Founder Command stores the handoff, delivery, SkyeMail provisioning response, QR payload, and backup status so client access can be audited later.

Security rule

Do not build a permanent client password spreadsheet. Use owner claim/reset links, key cards, reveal-safe handoff packets, and provider-backed mailbox receipts.
