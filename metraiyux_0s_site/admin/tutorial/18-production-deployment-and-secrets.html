18. Production Deployment and Secrets

How to move from local demo mode into a deployed Cloudflare Worker-backed automation layer with current proof and private secret custody.

Lesson steps

Deploy static site

Publish the site to Cloudflare Pages or another static host. Keep admin pages behind your upstream gate.

Refresh proof first

Run npm run 0s:build:proof so SkyeVault autosync proof, the proof log, and generated changelog module are current before deploy.

Deploy Worker

Use npm run 0s:worker:deploy. The deploy script runs autosync proof publishing and changelog generation before Wrangler deploy.

Create data stores

Apply migrations and bind D1, KV, Queue, and SITE_EVENTS_KV so chats, tasks, approvals, autosync notification settings, and email receipts persist.

Set secrets

Store ADMIN_TOKEN and RESEND_API_KEY as secrets, never in browser JavaScript or public proof files.

Bind resources

Attach resources in wrangler.toml and verify /api/admin/status plus /api/skyevault/autosync-notify-settings with owner auth.

Operator checklist

  • npm run vault:autosync:status returns the current repo digest.
  • npm run vault:autosync:proof writes the published proof files.
  • npm run vault:autosync:notify:status shows whether Resend update emails are enabled for the local daemon.
  • Worker deploy completed and the generated changelog module is fresh.
  • Resend approval and autosync email settings are tested with owner auth.
  • Approval inbox shows test records when approval email tests are run.

Proof rule

Do not mark this lesson complete until the related page, endpoint, token, connector, and SkyeVault autosync proof surface have been opened and tested. Local receipts are acceptable for demo mode; live claims require Worker/D1/provider proof and the live browser gate.
