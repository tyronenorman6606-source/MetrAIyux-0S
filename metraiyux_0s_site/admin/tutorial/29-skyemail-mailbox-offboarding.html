Provider seat control

SkyeMail mailbox offboarding

Use this when a client, workspace, or internal mailbox needs to be archived, released, or reassigned without losing proof. Founder Command is the owner hub; SkyeMail writes the mailbox status, offboarding receipt, FS27 mirror event, and Citadel backup event.

Open mailbox laneOpen API routeBack to tutorials

1. Find the mailbox

Open Founder Command, choose Mailboxes, then enter the mailbox email or workspace/client id. Use Check Status before changing anything.

2. Prepare first

Prepare Packet marks the mailbox as offboarding pending and creates the receipt. It does not claim the provider license is free yet.

3. Export the archive

Go to the provider admin console and export/archive the mailbox data before removing provider access. This protects client history and audit evidence.

4. Release the provider seat

Disable/delete the provider mailbox or reassign the license in the provider console. Only confirm this step after the provider shows the seat is available.

5. Confirm in SkyeMail

Check Archive/export complete and Provider seat released, then Confirm Seat Released. SkyeMail marks the mailbox released, disables aliases, and logs the receipt.

6. Reuse or reassign

After release, provision the next mailbox from SkyeMail/Founder Command. If a release was started by mistake, Cancel Offboarding restores the mailbox and aliases to active.

Operator rule

Do not delete a provider mailbox before archive/export is complete. Do not mark a mailbox released in SkyeMail until the provider seat is actually free. The API route is /api/founder-command/skyemail/offboarding and it stays behind the shared FS27/SkyGate/Free99 owner lane.
