One login truth

  1. The shared 0S/FS27/SkyGate/Free99 gate session is the owner/admin login.
  2. A signed SkyeVault download URL is only a short-lived file ticket minted after the gate accepts you.
  3. SkyeSecure passphrases and peppers unlock encrypted packs. They are not SkyeVault logins.
  4. Legacy admin/operator tokens are emergency fallback only when the shared gate is unavailable.

How secure packs move

  1. Load receipts to see what SkyeVault is holding for the signed-in workspace.
  2. If the object is a .skyesecrets pack, download it first. Your browser saves the encrypted file.
  3. Open the decrypt console, choose that downloaded file, inspect it, then enter the recipient passphrase and pepper if the sender used one. That is encryption unlock material, not a second login.
  4. If nobody gave you a passphrase or pepper, stop there. The vault can prove custody, but it cannot read the encrypted contents for you.

Literal full-repo custody lane

  1. Full now means an encrypted all-bytes repo stream, not the older filtered source-custody package.
  2. The daemon runs the delta journal first, then streams the encrypted full artifact to SkyeVault/R2 and writes the SkyeSecure control-pack handoff.
  3. Private signed artifact/control-pack links are minted only into local owner receipts such as .skyevault-out/autosync/latest-full-repo-download-links.json.
  4. Use the vault drive for custody, this dashboard for receipts, the local direct-download opener for temporary signed links, and SkyeSecure for unlock. Do not paste bearer tokens, passphrases, peppers, or signed URLs into public proof pages.
