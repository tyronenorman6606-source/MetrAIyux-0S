How admin works

The message path is public widget to Relay13 to operator inbox, with ConnectLog and FS27 proof around it.

1. Visitor sends

The website widget sends the message to /api/v1/conversations with workspace, account, route, and ConnectLog metadata.

2. Relay13 persists

Relay13 writes the conversation and messages to D1, returns a visitor token, and can open a Durable Object WebSocket room.

3. Admin operates

The Relay13 Console loads workspaces, conversations, message history, unread counts, and lets the operator reply live.

4. Gate tracks

SkyeGateFS27 mirrors messaging lane events for source app, workspace id, SKM account code, billable state, and proof status.

Brain route vs direct route

The widget can label the thread for a brain-assisted answer or direct operator handling.

Brain-assisted means the thread is routed with metadata so the Site Operator Brain or a cabinet brain can be used to draft an answer. Direct operator means the inbox is for Gray/operator review. The infrastructure is live today; automatic brain replies need the server-side brain bridge so the API key and private prompts stay out of public JavaScript.

Operator console checklist

Open Relay13 Console, paste the platform admin token, select ConnectLog Main, filter open threads, read the message history, reply as operator, then mark the thread pending or closed.

Use ConnectLog when the thread should become a relationship card, follow-up request, or customer/account opportunity.

Guardrails

Relay13 blocks abuse before the future brain responder gets a turn.

Customer chat stays on app knowledge. Web search is locked off for website replies, auto-reply defaults to draft-only, direct operator routes stay human-review routes, and prompt-injection or secret-extraction attempts are rejected before persistence.

Guardrail proof

The proof checks 0S, Bob, and Empire lanes for app-knowledge policy, no-web-search AI metadata, web-search review handling, and prompt-attack blocking.
