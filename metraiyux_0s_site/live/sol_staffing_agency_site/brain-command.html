Brain Command

Operator controls for the local staffing brain.

This page explains how the local brain is wired, what it can do now, what it cannot do yet, and how to upgrade it into a provider-backed or GPU-backed assistant later.

Truth Label

Static local brain.

Current brain is rule-based JavaScript + JSON. It is useful and deployable, but it is not an LLM until you connect a local model/API endpoint.

Current Brain

  • Runs inside browser
  • Uses JSON corpus
  • Uses keyword scoring
  • Routes to pages/forms
  • Stores localStorage memory
  • No API cost

Not Yet

  • No real LLM reasoning
  • No server database
  • No secure private memory
  • No file upload analysis
  • No ATS/CRM sync
  • No GPU model connection

Upgrade Path

  • Add Netlify Function
  • Add Cloudflare Worker
  • Add Ollama/GPU endpoint
  • Add vector search
  • Add authenticated memory
  • Add CRM/ATS tools

Brain Files

The local brain lives in the site package.

These files are included and deploy with the site. Edit the corpus to change the brain’s knowledge without touching the UI.

Future API Hook

Optional server-backed brain path.

Static mode: current site works with no backend.

Function mode: create /.netlify/functions/brain and let the page call it when enabled.

GPU mode: point the function at an Ollama/vLLM endpoint on your GPU server for real local-model answers.

Memory mode: replace localStorage with authenticated database memory when upstream auth is available.
