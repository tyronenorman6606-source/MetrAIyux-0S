# Real Telemetry Repair Register

Date: 2026-05-31

This register tracks places where a 0S surface could show local, demo, static, or preview activity as if it were production telemetry. The production rule is simple: customer-visible logs, analytics, event streams, workspace activity, deployment records, and mailbox status must come from live Worker/D1/KV/R2/provider paths or fail visibly. Browser cache is allowed only as cache/staging and must not be presented as the source of truth.

## Live Telemetry Spine

- `/api/0s-command-bridge/events`: shared 0S event ledger in `SITE_EVENTS_KV`, gate-authenticated for writes, operator-authenticated for reads.
- `/api/saas/action-event`: SaaS UI/action event lane; built-in main Worker fallback writes to `SAAS_KV` or `SITE_EVENTS_KV`.
- `/api/saas/customer-command`: live customer command receipt lane.
- `/api/saas/customer-visuals`: customer dashboard visuals from live workspace, commands, SaaS events, billing, SkyeMerit, SkyeMail status, and Command Bridge entity events.
- `/api/skymusicnexus/*`: SkyeMusicNexus live artist/release/analytics/playback endpoints.
- `/api/skyenet/*`: SkyeNet deploy/source/route/env/customer export control plane.
- `/api/profit/*`: SkyeProfitConsole Worker/KV runtime for review packs, close briefs, execution, dispatch, proof, and status.
- `/api/houseops/*`: HouseOperations Worker/KV runtime for tasks, vendors, schedule, alerts, assignments, proof, gate packets, queue, exports, and audit.
- `/api/marketing-made-easy/webcreator-runtime/*`: SkyeWebCreatorMax delivery-pack runtime under the Marketing Made Easy adapter.
- FS27 runtime observer, platform events, provider-runtime receipts, Citadel mirrors, and SkyErrors remain the reusable low-level lanes for request analytics, provider metering, dual-write/data parity, and error capture.

- Browser proof remains owner-handled under `.agents/live-browser-verifier/browser-proof-policy.toml`; production closure in this repo is build/deploy plus non-browser HTTP/API proof.
