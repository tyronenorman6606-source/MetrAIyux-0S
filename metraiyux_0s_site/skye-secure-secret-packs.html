End-to-end product story

From ignored secrets to encrypted, auditable, restorable developer custody.

When a client receives a repo, they should not receive a broken workspace and a nervous message about missing `.env` files. They should receive a complete operating handoff: safe source archive in the vault, encrypted secret pack in the vault, role-bound unlock, restore receipts, and a clean proof trail that says who packed, who opened, what restored, and what stayed private.

01 Scan

Read the secret boundary.

The app reads the same ignored/local-only paths that SkyeVault uses: `.env`, private keys, credentials, service accounts, database state, WAL archives, and approved local recovery files.

02 Review

Operator confirms paths.

The app shows file paths, sizes, reasons, and risk tags. It never prints secret values. Operators choose what belongs in the encrypted pack and what remains disposable.

03 Encrypt

Local encryption first.

A random content key encrypts the internal payload. User, team, recovery, and device keys wrap that content key without exposing plaintext to storage.

04 Upload

Vault stores ciphertext.

SkyeVault or Drive receives only the encrypted `.skyesecrets` pack, safe outer metadata, tamper fingerprints, and receipts.

05 Unlock

Approved dev opens app.

The dev downloads the pack, authenticates, unlocks a wrapped key, decrypts locally, and sees restore options for the target workspace.

06 Restore

Workspace becomes whole.

The app restores files into exact paths, warns before overwrites, records restore receipts, and keeps plaintext out of the normal repo push lane.

Package architecture

SkyeSecure v2 turns a document envelope into a full secret custody container.

SkyeDocxMax already has a secure envelope. SkyeSecure v2 generalizes it for developer packs, large payloads, team access, multi-recipient recovery, tamper detection, and platform integration.

Encrypted payload

payload/ files/ .env SkyeVault-Drop/.env private credential JSON local database recovery state restore-manifest.json restore-policy.json source-boundary.json redacted-preview.json Only the standalone app can reveal this tree after local decrypt.
A

Encrypted by design

Hashing is used for proof and tamper checks. Encryption is used for anything that must be opened again.

B

Key wrapping

The content key is never stored raw. It is wrapped for approved identities, recovery codes, and future device-bound keys.

C

Receipts without leakage

Public receipts prove pack creation and upload without revealing secret values or sensitive path bodies.

D

Restore discipline

Restore actions create local receipts, protect existing files, and keep plaintext outside Git history.
