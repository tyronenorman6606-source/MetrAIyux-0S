Overview

SkyeDrivePro is a sovereign file cloud direction designed to push well past generic upload-and-list behavior.

In the attached build, the worker remains the brain, D1 owns metadata and audit state, R2 holds file bodies and versions, and the browser keeps a local mirror through IndexedDB. That means the storage surface is not just remote. It has local persistence, offline queue behavior, reconnect sync, and pinned file handling built into the experience.

The repo also shows clear phased growth: multipart resumable transfers, search and preview lanes, conflict recovery, document parsing, thumbnails, a document studio, collaborative editing, and then a native bridge into SkyeDocxPro so editable files can open into a richer word-style editor without abandoning the drive control plane.

Product surfaces

Offline-first local mirror

Folders, files, and shares are mirrored into IndexedDB so the browser is not reduced to a dumb remote shell waiting for the network to bless it.

Sync and mutation journal

Folder and file actions are recorded into an offline mutation journal, then pushed and reconciled through sync endpoints when connectivity returns.

Versioned file storage

Uploads increment file versions and keep the storage surface aligned with R2-backed bodies and D1 metadata instead of flattening everything into a disposable blob.

Share and admin lanes

The product includes expiring public shares, activity ledgers, admin overview routes, and manifest visibility so the operator can inspect what is happening.

  • Resumable uploads

    Later phases add multipart uploads, per-part verification, retry-aware browser logic, and transfer session status routes for larger files.

  • Search and previews

    The attached roadmap and routes include text previews, search, indexing, and inline preview behavior for text-like files.

  • Conflict recovery

    Rename, move, and trash behaviors are tracked with version conflict handling so stale actions stop quietly smashing over newer state.

  • PWA delivery

    Manifest and service worker support are part of the product surface, which makes offline use a real capability rather than a marketing shrug.

Native .skye standard

One of the most important signals in this release is the promotion of the .skye package into a first-class native format. Secure files can be unlocked in the real SkyeDocxPro editor, shadow-saved into drive metadata for preview and search lanes, and committed back as encrypted .skye versions instead of being flattened into generic text.

Storage gets more powerful the moment the file format, the editor, and the control plane stop acting like strangers.

Why this matters

This is where the product stops being “a drive clone” and starts becoming part of a sovereign document system. The bridge into SkyeDocxPro turns storage, editing, versioning, and collaboration into one coherent lane.

Who it fits

SkyeDrivePro fits operators, document-heavy teams, and product owners who want a branded storage surface with real local persistence, versioning, sync logic, and room to expand into a larger document ecosystem. It is especially strong for people tired of treating file storage like a hostage situation with a nice icon.

Need a storage product that behaves like a system instead of a generic bucket browser?

SkyeDrivePro is designed for that exact job: branded ownership, real sync behavior, and a clear path into native document handling.
